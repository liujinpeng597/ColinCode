# One Click Start

仅在用户显式调用 `/one-click-start` 或明确要求一键启动脚本时使用，不要主动套用。

本技能**不生成停止脚本**；用户需要停止脚本时按普通任务处理。

## 执行步骤

### 1. 探明怎么启动

读入口文件、依赖清单、端口来源（配置文件或环境变量）与健康接口，确定两件事：**启动命令**，以及**判定「服务已就绪」的地址**。复用项目现有入口与启动方式；不要替换框架，也不要凭空引入虚拟环境。

### 2. 生成 start.bat

流程：环境检查 → 依赖存在性检查 → 端口探测 → 启动服务 → 轮询健康接口 → 打开浏览器。

- 依赖缺失时默认只提示并走失败路径；项目约定或用户明确要求时，才在脚本内用国内镜像安装。
- 健康接口已可达 → 只打开浏览器，不重复拉起第二个实例。
- 端口被占但健康接口不通 → 打印占用该端口的 PID 与通用停止命令交给用户，脚本自己不动手。探测要同时匹配 IPv4 与 IPv6 的监听行（`netstat` 里的 `[::]:port`）。
- 启动后按 1~2 秒间隔轮询健康接口，最长 60~120 秒，超时才判定失败。

### 3. 验证

把服务真正跑起来：执行脚本（环境禁止调用 `cmd.exe` 时，等价地执行脚本内的启动命令），用 `curl.exe` 轮询健康接口确认可达，并确认服务已在运行时不会重复拉起。结束后关掉本次拉起的进程、释放端口。

- 无法执行 `cmd.exe` 的场合，做静态检查并**明确说明这是降级验证**，不要声称跑通了窗口流程。
- 窗口、浏览器这类无法自动验证的行为，留给用户确认。

## 硬约束

- **纯 ASCII + CRLF**：命令、注释、`echo` 文本、窗口标题都用英文；生成后确认无裸 LF、无双 CR、无控制字符。
- **不硬编码项目路径**：`set "ROOT=%~dp0"`，去掉末尾反斜杠再拼接；带反斜杠的路径不要直接放进引号。
- **`if (...)` / `for (...)` 块内的 `echo` 不得有裸 `(` `)` `&` `|`**；块内改完变量要立刻读取时，用 `setlocal enabledelayedexpansion` + `!var!`。
- **关键命令后都要检查 `errorlevel`**。特别注意：`for /f ... | findstr ...` 无匹配会留下 `errorlevel=1`，而 `start` 成功时不清除它——在 `start` 前加 `ver >nul` 清一次。
- **每个子服务各开一个日志窗口**：`start "Title" /D "workdir" "%ComSpec%" /k "command"`。窗口标题只用于日志辨识，不要靠它识别或关闭进程。
- **失败路径统一跳 `:fail`**：说明原因 → `pause` → `exit /b 1`，不要静默退出。
- **健康检查地址**要与启动绑定地址、浏览器地址一致；不得只探测一次就报错。
- **`start.bat` 内不含杀进程、结束窗口、清理端口的逻辑**。
- **不把密钥写进 BAT、临时文件、命令行参数或日志**。
