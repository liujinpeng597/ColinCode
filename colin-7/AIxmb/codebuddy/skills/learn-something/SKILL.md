# Learn Something

## 目标

把用户输入的一个知识点整理成一份适合初学者阅读、可长期复习的 Markdown 笔记，并写入当前工作区。内容要解释清楚“是什么、为什么、怎么做、什么时候用、和什么容易混淆”，而不是只罗列术语。

## 输入与触发

- 接收一个明确的知识点，例如“Python 装饰器”“REST API”“数据库索引”或“二叉树”。
- 只在用户明确调用“$learn-something”，或明确说“为我创建某个知识点的 Markdown 学习笔记”时执行。
- 如果用户没有提供知识点，先询问要学习什么，不创建空文件。
- 如果输入包含多个知识点，只有在每个知识点边界清楚时才分别创建文件；否则先让用户选择一个主题。
- 默认使用当前工作区作为输出目录。用户指定目录或文件名时，遵循用户指定，但不得写入明显的运行时数据目录、虚拟环境目录或依赖目录。

## 文件命名与重复处理

- 使用知识点标题作为文件名，并追加 .md，例如“Python装饰器.md”。
- 保留中文、英文、数字、空格、下划线和连字符；将 Windows 不允许的字符（反斜杠、正斜杠、冒号、星号、问号、双引号、小于号、大于号、竖线）替换为连字符，去掉首尾空格和句点，并阻止 .. 等路径穿越片段。
- 清理后文件名为空时，先请求一个更适合作为文件名的知识点名称。
- 同名文件已存在时，先读取并判断内容：若它是同一知识点的笔记，则在原文基础上补全或修订，不要无提示地删除已有内容；若内容无关，则使用不冲突的后缀，例如“知识点-2.md”，并在结果中说明实际路径。

## 工作流程

1. 识别知识点的常见含义、适用范围和学习前提。若术语有多个含义，选择最常见的技术语境，并在定义中明确说明。
2. 根据主题复杂度组织内容。优先用直观类比、简短步骤和最小可运行示例；不要为了凑篇幅堆砌历史或边缘细节。
3. 对版本敏感、可能变化或不确定的技术细节，优先查阅官方文档或其他一手资料；无法核实时，明确标注假设和版本范围，不把猜测写成定论。
4. 按“文档模板”中的固定顺序写入 Markdown 文件。技术主题的代码示例必须标注语言；代码注释使用简体中文，并说明关键输入、输出和执行结果。
5. 写入后检查文件确实存在、标题与知识点一致、所有必需章节都有实质内容，并向用户报告文件的绝对路径。

## 文档模板

创建的文件至少包含以下结构，标题可以根据主题补充小节，但不得删除或改变主线顺序：

    # {知识点}

    > 一句话概括：{用初学者能理解的话说明它解决什么问题}

    ## 一、知识点定义
    {说明概念本身、核心组成、边界，以及必要的英文术语。}

    ## 二、作用
    {说明它解决的问题、带来的能力，以及它在整体流程中的位置。}

    ## 三、相关实现
    {先讲原理或步骤，再给最小示例；技术主题可包含代码、输入、输出和关键执行过程。}

    ## 四、使用场合
    {列出适合使用和不适合直接使用的典型场景。}

    ## 五、为什么要使用这个知识点或技术
    {从实际收益、替代方案、维护成本或学习目标说明使用动机。}

    ## 六、优点与缺点
    ### 优点
    - {优点及其成立条件}

    ### 缺点
    - {缺点、风险及规避方式}

    ## 七、相关或相近的知识点
    | 知识点 | 关系 | 适合继续了解的原因 |
    | --- | --- | --- |
    | {名称} | {相近、依赖、替代或上下游关系} | {说明} |

    ## 八、相关知识点之间的区别
    | 对比维度 | {当前知识点} | {相近知识点} |
    | --- | --- | --- |
    | 核心目标 | {说明} | {说明} |
    | 使用方式 | {说明} | {说明} |
    | 适用场景 | {说明} | {说明} |
    | 主要代价或限制 | {说明} | {说明} |

    {根据主题补充一个选择建议、常见误区或复习问题。}

## 内容质量要求

- 以简体中文为主，保留必要的英文技术术语，并在首次出现时解释。
- 面向正在学习编程的用户，先解释概念，再解释实现；避免只贴代码不解释代码为何这样写。
- 事实、示例和结论必须彼此一致。示例中的名称、参数、返回值、命令和输出不要互相矛盾。
- 对“优点”和“缺点”说明成立条件，避免使用“绝对更快”“一定安全”等未经验证的表述。
- “相关实现”必须贴合主题：编程概念给出最小代码或伪代码，设计思想给出流程，非技术概念给出可操作步骤。
- “区别”至少比较目标、工作方式、适用场景和主要代价；不要只写概念定义的重复内容。
- 如使用外部资料，可在文档末尾增加“## 参考资料”，只放实际查阅过的来源；不要捏造链接。

## 完成反馈

完成后用简短中文告知：

- 已创建或更新的文件绝对路径；
- 使用的知识点标题；
- 是否存在同名文件以及采取的处理方式；
- 若内容依赖特定版本、假设或未核实信息，明确提醒用户。
