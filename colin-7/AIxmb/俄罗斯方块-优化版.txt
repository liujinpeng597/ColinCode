你是一名资深前端工程师和游戏开发工程师。请使用原生 HTML、CSS、JavaScript 开发一个网页版俄罗斯方块游戏，生成一个可直接运行的三文件项目。

目标：游戏逻辑必须稳定，界面风格需要接近参考截图中的深色霓虹移动端俄罗斯方块界面。

## 一、输出要求

请只输出以下 3 个文件的完整代码：

1. `index.html`
2. `style.css`
3. `script.js`

要求：

- 不使用后端服务。
- 不使用构建工具。
- 不依赖第三方框架。
- 打开 `index.html` 后即可在浏览器中运行。
- HTML 中正确引入 `style.css` 和 `script.js`。
- 代码结构清晰，变量和函数命名语义明确。
- 不要省略任何核心逻辑，不要只给伪代码。
- 不要输出解释性文章，直接给出三个文件代码。

## 二、参考截图界面风格

请根据参考截图实现类似的视觉效果，重点是布局、颜色、层级和按钮形态，而不是逐像素复制。

整体风格：

- 深色游戏背景，主色为深蓝、黑蓝、藏青色。
- 页面具有轻微霓虹科技感，但不要使用复杂动画影响游戏性能。
- 顶部居中显示标题“俄罗斯方块”。
- 标题使用蓝色到紫色的渐变文字效果，字体较粗，醒目。
- 主棋盘周围有蓝绿色发光边框或阴影。
- 信息卡片使用半透明深灰蓝背景、浅色描边、圆角。
- 文字颜色以青色、白色为主，关键数字使用亮色突出。

布局结构：

- 页面整体优先适配手机竖屏，也要兼容桌面浏览器。
- 上方是标题。
- 中间主体区域为左右布局：
  - 左侧是主游戏棋盘，占据最大视觉面积。
  - 右侧是信息面板，纵向排列。
- 右侧信息面板从上到下依次包含：
  1. “下一个”方块预览区域。
  2. “得分”显示卡片。
  3. “等级”显示卡片。
  4. “行数”显示卡片。
  5. 开始/暂停按钮。
  6. 重置按钮。
- 底部是移动端控制区：
  - 左下方或中下方为灰色十字方向键。
  - 右侧为黄色圆形“落底”按钮。

棋盘视觉：

- 棋盘为 10 列 x 20 行。
- 棋盘背景为接近黑色的深蓝色。
- 每个格子要有细微网格线，网格线为深灰蓝或低透明浅蓝。
- 棋盘外框有圆角和发光阴影。
- 方块颜色鲜明，例如：
  - I 方块：青色。
  - O 方块：黄色。
  - T 方块：紫色。
  - S 方块：绿色。
  - Z 方块：红色。
  - J 方块：蓝色。
  - L 方块：橙色。
- 方块格子需要有轻微高光或阴影，让它们看起来像截图里的发光方块。

按钮视觉：

- 开始按钮为青绿到青色渐变，文字为白色。
- 暂停按钮可使用黄色到橙色渐变，文字为白色。
- 重置按钮为红色到粉红色渐变，文字为白色。
- “落底”按钮为黄色或橙黄色圆形按钮，文字为黑色或深色，尺寸明显大于普通按钮。
- 十字方向键为灰色半透明大按钮，四个方向中显示三角箭头符号。
- 所有移动端按钮都要有足够大的点击区域。

## 三、游戏基础规则

实现一个符合经典俄罗斯方块规则的游戏：

- 棋盘尺寸为 10 列 x 20 行。
- 使用 7 种标准方块：I、O、T、S、Z、J、L。
- 方块从棋盘顶部生成并自动下落。
- 方块可以左移、右移、旋转、加速下落、直接落底。
- 方块落到底部或碰到已固定方块后应锁定到棋盘。
- 锁定后生成下一个方块。
- 填满一整行时自动消除该行，并让上方方块下移。
- 支持一次消除多行。
- 当新方块生成位置被占用时，游戏结束。

## 四、核心功能

必须实现以下功能：

- 游戏开始。
- 暂停或继续。
- 重新开始。
- 当前分数显示。
- 已消除行数显示。
- 等级或速度显示，消除行数越多，下落速度越快。
- 下一个方块预览。
- 游戏结束提示。
- 移动端可用的屏幕控制按钮。
- PC 键盘和移动端按钮都能完整控制游戏。

状态要求：

- 初始状态显示开始按钮。
- 游戏运行后，开始按钮文字变为“暂停”。
- 暂停后按钮文字可变为“继续”。
- 点击重置后，棋盘、分数、等级、行数、当前方块和下一个方块全部重置。

## 五、键盘控制

请实现以下按键响应：

- `W`：旋转当前方块。
- `A`：当前方块向左移动一格。
- `D`：当前方块向右移动一格。
- `S`：当前方块加速向下移动一格。
- `Space`：当前方块直接落底并锁定。

要求：

- 按键大小写都要支持。
- 按空格时不要让页面滚动。
- 游戏结束后，移动和旋转按键不应继续改变棋盘。
- 暂停状态下，移动和旋转按键不应继续改变棋盘。

## 六、移动端控制

页面底部或棋盘附近需要提供适合手机点击的虚拟按钮：

- 十字方向键：
  - 上：对应 `W`，旋转方块。
  - 左：对应 `A`，左移方块。
  - 下：对应 `S`，加速下落一格。
  - 右：对应 `D`，右移方块。
- 单独提供一个“落底”按钮，对应 `Space`，让方块直接落底。

移动端要求：

- 按钮尺寸足够大，适合手指点击。
- 点击按钮时不要触发页面缩放或滚动。
- 触摸按钮必须正确处理快速连续点击，连续点按时每次点击只触发一次对应操作，不能一次点击触发多次。
- 需要避免 `touchstart`、`touchend`、`click` 或 Pointer 事件重复绑定导致的一次触摸执行多次逻辑。
- 左移、右移、下移按钮可以支持长按连续触发，但手指松开后必须立即停止连续触发。
- 旋转按钮和落底按钮默认按一次只触发一次，不要因为长按而重复旋转或重复落底。
- 快速连点不同方向按钮时，输入响应要稳定，不能卡住、丢失或积压异常操作。
- 页面在手机竖屏下布局正常，不应出现主要内容被遮挡或横向溢出。
- 底部控制区不能遮挡棋盘和右侧信息面板。
- 桌面端和移动端都要有良好显示效果。

## 七、实现细节约束

请确保实现稳定，不要出现以下问题：

- 方块不能移动到棋盘外。
- 方块不能穿过已固定方块。
- 方块旋转时不能进入非法位置。
- 方块落底后必须正确锁定，不能继续移动。
- 消行后棋盘数据和画面必须同步。
- 下一个方块预览必须显示真实的下一个方块，而不是重新随机一个。
- 游戏结束后应停止自动下落。
- 重新开始后应清空棋盘、重置分数、行数、等级和游戏状态。
- 快速连续按键时，游戏状态不能混乱。
- 暂停、继续、重置时不能产生多个重复的下落定时器。
- 触摸按钮在快速连点时不能因为事件穿透或重复监听而一次触发多次移动、旋转或落底。
- 长按左移、右移、下移按钮时，连续触发频率要可控，不能快到导致越界或状态错乱。
- 手指离开按钮、触摸取消、页面失焦或切换暂停状态后，所有长按产生的连续移动或加速都必须立刻停止。

如果实现旋转墙踢，请保持逻辑简单稳定；如果不实现复杂墙踢，也必须保证旋转失败时方块保持原位置，不要越界或重叠。

## 八、界面实现要求

- 使用 Canvas 或 DOM 网格均可，但渲染逻辑必须稳定。
- 如果使用 Canvas，需要保证高清屏下画面清晰。
- 如果使用 DOM 网格，需要保证 10 x 20 格子尺寸稳定，不因内容变化而抖动。
- 棋盘格子边界清晰。
- 不同方块使用不同颜色。
- 显示区域至少包含：游戏标题、棋盘、分数、行数、等级、下一个方块预览、开始/暂停/继续按钮、重置按钮、移动端控制按钮。
- UI 简洁清晰，不要做复杂动画导致逻辑不稳定。
- CSS 需要包含响应式布局，兼容桌面和手机屏幕。
- 在手机竖屏下，棋盘和右侧信息栏应尽量保持截图中的比例：棋盘宽，信息栏窄，底部控制按钮居中分布。
- 页面不应出现横向滚动条。
- 所有文字必须在按钮和卡片内部完整显示，不能溢出或重叠。

## 九、建议计分规则

可以使用以下经典计分规则，保持简单稳定：

- 消除 1 行：100 分 x 当前等级。
- 消除 2 行：300 分 x 当前等级。
- 消除 3 行：500 分 x 当前等级。
- 消除 4 行：800 分 x 当前等级。
- 每消除 10 行提升 1 个等级。
- 等级越高，自动下落间隔越短，但需要设置最低间隔，避免速度过快导致不可玩。
